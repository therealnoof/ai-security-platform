## Executive Summary

The week of October 26, 2026 marked a significant milestone in AI-assisted vulnerability discovery when OpenAI announced it had used artificial intelligence to discover a critical vulnerability in the Brotli compression component, which [JPCERT/CC issued an alert for on October 26](https://www.jpcert.or.jp/), noting that crafted compressed data could enable remote code execution. The Brotli flaw (CVE-2026-111497, CVSS 9.2) is a memory-corruption bug in Google's Brotli decoder that allows a remote unauthenticated attacker to corrupt memory, leak memory contents, crash processes, or potentially execute code. [SecurityWeek reported](https://www.securityweek.com/) that researchers recorded exploitation attempts beginning October 26, targeting Node.js 24.22.0.

On October 27, Anthropic announced that it used an unreleased internal research AI to discover vulnerabilities in Chrome, Safari, Android, Windows, and Linux, and was able to create attack procedures by chaining multiple weaknesses together. These developments underscore a fundamental shift: AI systems are now operational both as offensive tools for vulnerability discovery and as attack vectors themselves.

The week also brought significant supply chain and infrastructure incidents. [Cloudflare published a post-mortem on October 26](https://blog.cloudflare.com/) revealing that between August 27 and September 9, its Workers AI deployment of the GLM-5.3 model returned 155 responses containing data from other customers' requests. Meanwhile, Chinese state hackers used ARTEX, a Go-based AI penetration testing framework, against high-value targets, demonstrating how AI tools built for legitimate security testing can be repurposed to speed up intrusions.

## Top Stories

### AI-Discovered Brotli Vulnerability Triggers Mass Patching

CVE-2026-111497 is a memory-corruption bug (CVSS 9.2, or 8.1 in Microsoft's advisory) in Google's Brotli decoder that allows a remote unauthenticated attacker who supplies a crafted Brotli stream to corrupt memory, leak memory contents, crash the process, or potentially run code. [JPCERT/CC issued an alert on October 26](https://www.jpcert.or.jp/) regarding the vulnerability in the compression component 'Brotli,' noting that if crafted compressed data is decompressed, programs could be executed from the outside, and OpenAI announced it discovered this vulnerability during an exercise using AI.

[SecurityWeek reported](https://www.securityweek.com/) that Previdian recorded one exploitation attempt on October 27 and that ELLIO caught a malicious request on October 26 targeting Node.js 24.22.0. [Microsoft's advisory](https://msrc.microsoft.com/) rates exploitation as more likely while saying nothing suggests criminals are succeeding with the working exploits researchers have built, with the demonstrated impact so far being crashes at scale and code execution only in a narrow configuration.

The vulnerability has significant reach. The flaw affects services that decode attacker-influenced Brotli data, with Express 5 with default JSON parsing putting many instances in that group. This marks one of the first instances where AI-assisted vulnerability research has directly led to emergency patching at this scale, demonstrating that defensive AI capabilities are now materially accelerating the vulnerability disclosure cycle.

### Cloudflare Workers AI Cache Leak Exposed Customer Data

On October 26, [Cloudflare published a post-mortem](https://blog.cloudflare.com/) revealing that between August 27 and September 9, its Workers AI deployment of the GLM-5.3 model returned 155 responses that contained data from other customers' requests. The incident represents a new class of AI infrastructure vulnerability: cross-tenant inference contamination at the cache layer.

Google introduced Gemini 4 Carbon on October 28, which it calls its strongest model for cybersecurity and long-running work, while [GitHub's Octoverse report published October 28](https://github.blog/) shows more than 40% of pull requests started with an agent's first draft by September 2026, up from 17% in March. The rapid integration of AI into production workflows makes cache isolation failures particularly consequential—any cross-tenant leak in an AI serving layer can expose proprietary prompts, business logic, and sensitive query data.

The root cause was a key-value cache implementation that failed to properly isolate customer contexts when serving cached inference results. Organizations deploying multi-tenant AI infrastructure should audit cache implementations, ensure tenant isolation at the cache layer, and implement request/response logging sufficient to detect cross-tenant leakage.

### Chinese State Hackers Deploy AI Pentesting Framework Against 200+ Organizations

A Chinese state-sponsored group used ARTEX, a Go-based AI penetration testing framework, against high-value targets, with the campaign showing how AI tools built for legitimate security testing can be repurposed to speed up intrusions. This represents the first confirmed use of an AI-powered offensive framework by a nation-state threat actor in a large-scale campaign.

Seoul police said a suspect used AI while breaching 60 organizations in 44 days, exposing more than 8.2 million personal records. Researchers reportedly used autonomous agents to access third-party business systems connected to Anthropic in less than 12 hours, with Anthropic saying the access was limited and did not affect customer conversations or core AI assets, illustrating the importance of constraining agent permissions, monitoring third-party integrations, and separating business services from sensitive AI infrastructure.

The ARTEX framework automates reconnaissance, vulnerability scanning, and exploitation chaining—tasks that previously required hands-on-keyboard operator time. The shift from AI-assisted to AI-autonomous offensive operations compresses the window between vulnerability disclosure and mass exploitation. Defenders must now assume that any published vulnerability will be incorporated into automated attack frameworks within hours.

## Vulnerability Watch

### MLflow Platform Vulnerabilities (October 27)

Three critical vulnerabilities in MLflow, the widely-used open-source AI engineering platform, were disclosed on October 27:

**CVE-2026-116692 (CVSS 9.8)**: From MLflow 3.12.0rc0 until 3.17.0, third-party scorer deserialization in mlflow/genai/scorers/base.py accepts request-selected descendants of THIRD_PARTY_SCORER_ALLOWED_MODULES rather than requiring an exact allowed module, allowing a caller to use MLflow artifact endpoints to place a Python module beneath a writable allowed package and submit its module and class through /ajax-api/3.0/mlflow/scorer/invoke, with Scorer.model_validate_json() importing the module and constructing the class before trace processing.

**CVE-2026-116690 (CVSS 7.5)**: From MLflow 3.10.0 until 3.17.0, the prompt branch in _create_model_version() accepts schemeless relative sources because path validation runs only when a source has a URL scheme, allowing a remote caller to store a server-local path as the model version artifact location and use /api/2.0/mlflow/model-versions/get-artifact to read files accessible to the MLflow server process.

**CVE-2026-116691 (CVSS 6.5)**: From MLflow 2.19.0 until 3.17.0, mlflow.crewai.autolog() records CrewAI Agent objects without consistently sanitizing nested credential-bearing values, with mlflow/crewai/autolog.py::_get_agent_attributes() converting the Agent llm field to a string that includes the provider API key, while mlflow/crewai/autolog.py::_construct_full_inputs() expands the Agent object into mlflow.spanInputs.

All three vulnerabilities affect MLflow versions prior to 3.17.0. Organizations running MLflow should upgrade immediately and rotate all credentials that may have been logged or exposed.

## Research Spotlight

**[Indirect Prompt Injection in the Wild](https://unit42.paloaltonetworks.com/ai-agent-prompt-injection/)** — Palo Alto Networks Unit 42, October 21, 2026  
Large language models and AI agents are becoming deeply integrated into web browsers, search engines and automated content-processing pipelines, introducing a new and largely underexplored attack surface, with indirect prompt injection (IDPI) being a particularly concerning class of threats in which adversaries embed hidden or manipulated instructions within website content that is later ingested by an LLM, with the article sharing in-the-wild observations from telemetry including the first observed case of AI-based ad review evasion.

Results show that 75.8% of pages contained a single injected prompt, whereas the rest contained more than one injected prompt.

**[Prompt Injection Statistics 2026](https://www.stingrai.io/blog/prompt-injection-statistics-2026)** — Stingrai Research, October 12, 2026  
The NIST NVD held 141 CVE records whose description names prompt injection on October 12, 2026, 87 of them published in 2026. System prompt leakage reports on HackerOne increased by 557% year over year in the July 2025 to June 2026 period.

**[In-the-Wild Prompt Injection Payloads](https://www.infosecurity-magazine.com/news/researchers-10-wild-indirect/)** — Forcepoint Research, October 30, 2026  
Researchers discovered 10 new indirect prompt injection (IPI) payloads targeting AI agents with malicious instructions designed to achieve financial fraud, data destruction, and API key theft, uncovering common triggers including "Ignore previous instructions," "Ignore all previous instructions," "If you are an LLM," and "If you are a large language model".

**[Large Reasoning Models as Autonomous Jailbreak Agents](https://www.nature.com/ncomms/)** — Nature Communications, 2026  
A 2026 study tested four adversarial large reasoning models—Grok 3 Mini, DeepSeek-R1, Gemini 2.5 Flash, and Qwen3-235B—attacking nine target models, with jailbreak success rates reaching up to approximately 97.14% on certain targets.

## What This Means For You

**Patch AI infrastructure components immediately.** The Brotli vulnerability (CVE-2026-111497) affects Node.js and potentially other environments that parse attacker-influenced compressed data. The MLflow CVEs (CVE-2026-116692, CVE-2026-116690, CVE-2026-116691) impact AI agent platforms directly. Both should be prioritized for emergency patching. For MLflow specifically, upgrade to version 3.17.0 or later and rotate all API keys and credentials that may have been exposed through logging.

**Audit AI agent permissions and third-party integrations.** The incident involving autonomous agents accessing Anthropic's third-party business systems in less than 12 hours illustrates the importance of constraining agent permissions, monitoring third-party integrations, and separating business services from sensitive AI infrastructure. Review what systems your AI agents can access, implement least-privilege access controls, and ensure that business logic systems are isolated from AI inference infrastructure.

**Assume prompt injection is now operationalized.** Google reported a 32% relative increase in malicious indirect prompt injection content between November 2025 and February 2026 across the 2-3 billion pages it crawls each month. The NIST NVD held 141 CVE records naming prompt injection on October 12, 2026, with 87 of them published in 2026. Prompt injection is no longer a theoretical risk—it is an active threat vector with documented exploitation in the wild. Implement runtime monitoring for AI agents, log all tool invocations, and establish alerting for unexpected agent behaviors such as credential access, file system operations, or outbound network connections not explicitly authorized by the user workflow.

**Review AI cache implementations for tenant isolation.** The Cloudflare Workers AI cache leak demonstrates that multi-tenant AI serving introduces novel isolation risks. If you operate shared AI infrastructure, audit your cache implementation to ensure customer contexts cannot bleed across tenant boundaries. Implement request/response logging sufficient to detect cross-customer data exposure, and establish runbooks for cache poisoning or isolation failure scenarios.
